# P4 界面设计任务书（在 Mac 上完成）

给在负责人 Mac（Apple Silicon M1）上运行的 Claude Code。P4 的完成标准：**在 Mac 上能用我们的桌面应用完成一个完整的建模流程**（打开或新建流 → 接数据源 → 字段处理 → 训练模型 → 看结果和打分），并打包成 `.app`/`.dmg`。

负责人选择在 Mac 上做界面，原因是 Modeler 在 Mac 上的适配很差。所以这次的方向是 **Mac 优先**：体验按 macOS 的标准做好。但应用仍必须在 Windows x64 上编译和运行（AGENTS.md：两个平台都是主平台）。

开始前读：`AGENTS.md`（全部规则仍然有效）、`docs/architecture.md`、`ROADMAP.md`、`docs/parity-checklist.md`（节点清单）、`docs/mac/MAC_REPORT.md`（这台 Mac 的环境）。

## 1. 现状：界面之下还缺什么

| 部分 | 现状 | 界面需要的 |
|---|---|---|
| L0–L3 | 完成：类型、`.str` 解码、流结构、CLEM、IO、算法、执行器。`dms-cli run` 能跑完整的流 | 只需调用 |
| L1 `dms-stream` | 只有从 `.str` 解析出的结构；**没有原生保存格式**，也不能编辑 | 编辑操作；原生文本格式（TOML 或 JSON，可 git diff，`#[serde(default)]` 保证旧文件可读，导入 `.str` 时未识别的节点和参数原样保留） |
| L4 `dms-engine` | 只有节点目录（`catalog.rs`、`nodes.rs`）；**没有命令注册表、Session、撤销** | 命令注册表、Session、撤销/重做、长任务（进度、取消） |
| L6 `dms-ui`、应用 `dms` | 不存在 | 本任务 |

所以 P4 不只是画界面，还要先在 L1 和 L4 补上编辑、保存、命令、撤销。这些都在无界面的层里，要有单元测试，并且必须在 Windows 上同样通过。

## 2. 硬约束（不可违反）

### 架构

- **分层**：新 crate `dms-ui`（L6）和应用 `dms`（apps）登记在 `xtask/src/layers.rs`。`egui`、`eframe`、`winit`、`rfd`、`muda` 等界面库只能出现在 L6 和 apps 里；`cargo xtask layers` 必须通过。
- **一切都是命令**：每个用户可见操作都是 `dms-engine` 里带 id 的命令。命令有 id、标签、所在菜单或面板、快捷键、参数说明、`enabled` 判断、`run`，并且有测试。界面、CLI、以后的 MCP 都按 id 调用命令。界面里不写业务逻辑；程序调用命令时不弹对话框。
- **界面薄且数据驱动**：界面状态（窗口布局、选中项、缩放、面板开合）可以序列化。界面改动用离屏渲染截图来验证（`egui_kittest` 一类），截图测试要能在 CI 里跑。
- **数据类型是运行时数据**：存储类型、测量级别、角色、缺失值、日期基准都从数据和流设置里来，界面不写死。

### Never crash

- 非测试代码禁止 `unwrap`、`expect`、`panic!`、`unreachable!`、`todo!`、`unimplemented!`，禁止 `unsafe`（工作区 lints 已强制）。
- 训练、执行流、读大文件都在后台 worker 里运行：用 `catch_unwind` 包住，可以取消，出错时报告错误。界面不能卡在"运行中"，也不能因此闪退。
- 用户的流可能是几小时的工作。保存要原子化（先写临时文件再改名），崩溃或断电不能丢数据；建议有自动保存或恢复机制。
- 来自文件和用户输入的数字都视为不可信：取下标用 `get()`，分配前设上限。

### 净室（界面部分）

- 不使用 IBM 的图标、文案、配色、布局截图；仓库里不放任何 Modeler 截图。
- 可以把 Mac 上的 Modeler 当作普通用户使用，以理解工作流程和概念（节点、流、模型块、类型节点等），但界面要按我们自己的设计重新做，不能照着摆。
- 节点名称沿用 `crates/engine/src/catalog.rs` 里已有的名字（它们是功能名称，对标用）；节点图标我们自己画（或用宽松许可的图标集，登记来源和许可证）。
- 不读 GPL、LGPL、AGPL 软件的代码。同类数据挖掘软件 KNIME、Orange、Weka 都不看代码。

### 依赖

- 只用宽松许可（MIT、Apache-2.0、BSD、Zlib、ISC）的依赖。每个新依赖在设计文档里登记：名字、版本、许可证、用途。
- 版本固定在 `Cargo.toml` 的 `[workspace.dependencies]`；确认它们支持仓库固定的 Rust 1.95.0。
- 不引入 WebView、Electron、Tauri、JavaScript/TypeScript，不做 WebAssembly（已定决策）。

## 3. 可以参考的开源库和资料

| 类别 | 例子 | 用法 |
|---|---|---|
| egui 生态库（宽松许可） | `egui`/`eframe`（wgpu 后端，Mac 上用 Metal）、`egui_plot`、`egui_extras`（大表格虚拟滚动）、`egui_dock` 或 `egui_tiles`（停靠面板）、`egui-snarl`（节点图画布）、`egui_kittest`（界面测试、截图）、`rfd`（原生文件对话框）、`muda`（macOS 原生菜单栏） | 可以直接依赖，可以读源码和示例 |
| 宽松许可的大型 egui 应用 | Rerun 查看器（MIT/Apache） | 参考架构做法：界面状态管理、命令分发、测试方式 |
| 设计规范 | Apple Human Interface Guidelines | Mac 体验的依据 |
| 不可参考 | KNIME、Orange、Weka（GPL）的代码；Modeler 的图标、文案、配色 | — |

采用节点图库前先评估：缩放、平移、触控板手势、上百个节点时的性能、连线样式、能否把画布状态序列化。不合适就自己在 egui 上写画布。

## 4. Mac 体验要求（这次的重点）

- **原生菜单栏**（屏幕顶部）和 Cmd 快捷键：⌘N、⌘O、⌘S、⌘⇧S、⌘Z、⌘⇧Z、⌘W、⌘Q、⌘,（设置）、⌘R（运行）等，符合 Apple HIG。Windows 上用窗口内菜单和 Ctrl 快捷键，由同一套命令生成。
- **触控板**：双指平移画布，捏合缩放，惯性滚动自然。
- **Retina**：图标和文字在高分屏上清晰，图标用矢量或提供 2x 资源。
- **外观**：跟随系统的浅色和深色模式。
- **字体**：系统字体；界面文字必须能显示中文和捷克语等带变音符号的字符（团队数据里有捷克语路径和内容）。
- **窗口**：记住窗口大小、位置、面板布局；支持全屏；可以把 `.str` 文件或数据文件拖进窗口打开。
- **性能目标**：画布上 200 个节点时保持流畅（60 fps）；数据预览百万行时滚动不卡（虚拟滚动）；启动到可操作不超过 2 秒。
- **无障碍**：egui 的 AccessKit 支持保持开启。

## 5. 第一版界面范围

主窗口建议包含以下部分，布局由你设计：

1. 节点面板：按类别列出节点；只把已实现的节点设为可用（见 `crates/engine/src/nodes.rs`），未实现的显示为不可用并说明原因（以后再做、许可证受阻、不做）。
2. 流画布：添加、连线、移动、删除、复制粘贴节点；超节点可以先只显示，不编辑。
3. 属性面板：选中节点的设置。按节点类型从设置模式生成表单，不为每个节点手写界面。
4. 结果区：表格输出、数据预览、统计输出、模型块（树、系数、规则）、图表（`egui_plot`）。
5. 运行：运行整个流或单个终端节点；显示进度，可以取消；出错时指出是哪个节点、什么原因。
6. 文件：导入 `.str`（未识别的节点和参数原样保留，并在界面上提示）；用原生格式保存和打开。

## 6. 工作方式和阶段

在分支 `gui-design` 上工作，只提交到这个分支，不碰 `main`。每个阶段结束推送并停下，等负责人和 Windows 端审查后再继续。

### 阶段 A：设计文档和技术验证（先做这个）

1. 写 `docs/gui/DESIGN.md`，内容包括：
   - 主窗口布局（ASCII 线框图，或者我们自己做的示意图）、主要交互流程；
   - 命令清单（id、标签、快捷键、所在菜单）；
   - L1 编辑模型和原生保存格式的设计；L4 命令注册表、Session、撤销、长任务的接口设计；
   - 界面状态的序列化和截图测试方案；
   - 依赖清单（名字、版本、许可证、用途）；
   - 风险和待负责人决定的问题。
2. 技术验证（spike）：做一个最小的 `dms` 应用。在 Mac 上打开一个语料里的 `.str`（例如 `corpus/team/` 下的流），把节点和连线画在画布上，可以平移和缩放，原生菜单栏能用，有一个离屏截图测试。目的只是验证 eframe + wgpu/Metal、节点画布库、原生菜单、截图测试这套组合可行，代码以后可以重写。
3. `cargo xtask ci` 在 Mac 上通过。新 crate 也要能在 Windows 上编译：不要用只有 macOS 才有的 API，除非用 `cfg` 隔开并给出 Windows 的实现。
4. 推送 `gui-design`，用中文向负责人汇报，然后停下。

### 阶段 B 起：实现

等阶段 A 审查通过后，按设计文档的顺序实现：先补 L1/L4，再做界面。每一步都要能编译、有测试、`cargo xtask ci` 通过。
